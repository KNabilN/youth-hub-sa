

# خطة تحسين مسار ما بعد الشراء

## المشكلة
بعد إتمام عملية الشراء بكود الخصم، يبدو أن الجمعية لم تُوجَّه لصفحة النجاح بشكل صحيح (ظهرت السلة فارغة). هذا قد يحدث إذا فشل أحد الاستدعاءات أثناء `handleCheckout` قبل الوصول لـ `navigate("/payment-success")` — الخطأ يُبتلع بدون إعادة توجيه واضحة.

## الحل المقترح — على مستويين

### 1. إصلاح تقني: ضمان التوجيه لصفحة النجاح دائماً
- في `Checkout.tsx`، نقل `clearCart` و`navigate` ليتم تنفيذهما حتى لو فشلت بعض العمليات الثانوية (الإشعارات، الضمان المالي)
- فصل العمليات الأساسية (إنشاء المشروع + العقد) عن العمليات الثانوية (إشعارات، escrow) بحيث لا يمنع فشل الثانوية التوجيه

### 2. تحسين UX: أفضل خط سير بعد الشراء

**المسار الحالي:**
سلة → مراجعة → دفع → صفحة نجاح (مع أزرار: العقود / لوحة التحكم / الفواتير)

**المسار المقترح المُحسّن:**

```text
شراء ناجح
    │
    ▼
صفحة نجاح مُحسّنة
    ├── رسالة تأكيد واضحة ✓
    ├── ملخص الطلب (اسم الخدمة + المزود) ✓
    ├── خطوات قادمة واضحة (Journey Timeline):
    │   1. ✅ تم الشراء
    │   2. 🔄 العقد جاهز للمراجعة
    │   3. ⏳ بدء التنفيذ
    │   4. ⏳ تسليم المشروع
    │
    ├── زر رئيسي: "مراجعة العقد" → /contracts
    ├── زر ثانوي: "التواصل مع المزود" → /messages
    └── زر ثالث: "العودة للوحة التحكم"
```

### التغييرات المطلوبة

| الملف | التغيير |
|---|---|
| `src/pages/Checkout.tsx` | فصل العمليات الأساسية عن الثانوية + ضمان التوجيه حتى لو فشلت عملية ثانوية |
| `src/pages/PaymentSuccess.tsx` | إضافة Journey Timeline لمسار الشراء العادي + زر "التواصل مع المزود" + عرض اسم الخدمة والمزود |

### تفاصيل التحسين في صفحة النجاح
- إضافة `serviceTitles` و`providerNames` ضمن الـ state المُمرر من Checkout
- عرض timeline مرئي يوضح المراحل القادمة (مشابه لما يظهر حالياً في التحويل البنكي)
- إضافة زر "التواصل مع المزود" يوجه لصفحة الرسائل
- الإبقاء على الأزرار الحالية (العقود + لوحة التحكم + الفواتير)
