# خطة: تحسين قسم العقود + رؤية كاملة للأدمن

## المشكلة
- العقد الحالي يعرض فقط "نطاق العمل" (يدخله الأدمن/الجمعية يدوياً) ولا يجمع المدخلات السابقة لمزود الخدمة.
- لا تظهر تفاصيل العرض (الوصف، السعر، المدة، خطاب التغطية) ولا تفاصيل المشروع/الخدمة الأصلية بصياغة تعاقدية.
- صفحة الأدمن للعقود تعرض جدولاً فقط بدون قدرة على معاينة العقد كاملاً.

## الحل

### 1. توليد محتوى العقد تلقائياً عند الإنشاء
عند إنشاء أي عقد (في كل النقاط: قبول العرض، شراء خدمة، تحويل بنكي، Edge function للدفع) نُنشئ **مقدمات تعاقدية موحّدة** تُخزَّن في `terms` كـ JSON منظّم (أو نص مهيكل بأقسام واضحة). الحقول:

- **معلومات الأطراف**: اسم الجمعية + اسم المزود + أرقامهم في المنصة + رقم العقد.
- **موضوع العقد**: عنوان المشروع/الخدمة + رقم الطلب + الفئة.
- **وصف الخدمة**: من `projects.description` أو `micro_services.description`.
- **مدخلات مزود الخدمة من العرض**: 
  - خطاب التغطية (`bids.cover_letter`)
  - السعر (`bids.price`)
  - المدة الزمنية (`bids.timeline_days`)
- **التزامات الطرف الأول (الجمعية)**: دفع المبلغ عبر الضمان، تزويد المواد المطلوبة، مراجعة التسليمات في وقت معقول.
- **التزامات الطرف الثاني (المزود)**: تنفيذ النطاق المتفق عليه، الالتزام بالمدة، تقديم التسليمات للمراجعة.
- **التفاصيل المالية**: قيمة العقد، طريقة الدفع، آلية الضمان.
- **البنود العامة**: نفس الخمس بنود القانونية الموجودة حالياً.

التنفيذ: دالة helper `buildContractTerms({ project, bid, association, provider, amount })` في `src/lib/contract-terms.ts` تُستخدَم في كل نقاط الإنشاء.

### 2. صفحة عرض العقد بصياغة تعاقدية رسمية (`ContractReviewPanel`)
- Hero بشكل مستند رسمي: شعار المنصة + رقم العقد + حالة التوقيع + التاريخ الهجري والميلادي.
- أقسام مرقّمة (المادة الأولى — التعريفات / الثانية — موضوع العقد / الثالثة — نطاق العمل والتزامات المزود / الرابعة — التزامات الجمعية / الخامسة — المقابل المالي / السادسة — مدة التنفيذ / السابعة — الضمان والتسليمات / الثامنة — البنود العامة / التاسعة — التوقيعات).
- صناديق توقيع للطرفين أسفل العقد (مع التاريخ والاسم بعد التوقيع).
- زر **"تحميل PDF"** — يُولِّد نسخة PDF من نفس المحتوى باستخدام موارد PDF الموجودة في المشروع (`src/lib/pdf-utils.ts`, `src/components/pdf/`).
- زر **"طباعة"** عبر `window.print()` مع print stylesheet مخصص.
- إبقاء التعديل على "نطاق العمل" متاحاً للجمعية قبل التوقيع، مع إضافة حقول قابلة للتعديل لـ"الالتزامات الإضافية" (اختياري).

### 3. عرض كامل للعقد للأدمن
- صفحة جديدة `src/pages/admin/AdminContractDetail.tsx` على المسار `/admin/contracts/:id`:
  - تستخدم نفس مكوّن `ContractReviewPanel` (read-only للأدمن).
  - تعرض: العقد الكامل، نسخه السابقة (`contract_versions`)، حالة الضمان المالي، الفواتير المرتبطة، التسليمات، مرفقات العقد، سجل النشاط.
  - أزرار: "تحميل PDF"، "عرض المشروع"، "عرض المحادثات".
- في `AdminContracts.tsx`: زر "عرض العقد" بجانب "عرض المشروع" يفتح الصفحة الجديدة.
- إضافة Route في `App.tsx`.

### 4. تحسينات بصرية للعقد (UI)
- Watermark خفيف "نسخة عقد" أو "غير موقّع" حسب الحالة.
- Border و typography يحاكي مستند رسمي (خط مميز للعناوين).
- في حالة `signed` بالكامل: ختم "موقّع رسمياً" مع التاريخ.

### 5. ملفات سيتم تعديلها/إنشاؤها
**جديدة:**
- `src/lib/contract-terms.ts` — دالة بناء محتوى العقد المهيكل.
- `src/pages/admin/AdminContractDetail.tsx` — صفحة الأدمن.
- `src/components/contracts/ContractDocument.tsx` — مكوّن المستند الرسمي (مستخدم في PDF + الصفحة).

**معدّلة:**
- `src/components/contracts/ContractReviewPanel.tsx` — إعادة هيكلة العرض + قراءة الـ terms المهيكل + زر تحميل PDF.
- `src/hooks/useContracts.ts` — تعديل `useUpdateContractTerms` ليحدّث القسم القابل للتعديل فقط دون مسح الباقي.
- نقاط إنشاء العقد:
  - `src/components/bids/BidPaymentDialog.tsx`
  - `src/hooks/usePurchaseService.ts`
  - `src/hooks/useBankTransfer.ts`
  - `src/pages/Checkout.tsx` (3 مواضع)
  - `supabase/functions/moyasar-verify-payment/index.ts` (نسخة موازية في الـ edge function)
- `src/pages/admin/AdminContracts.tsx` — زر "عرض العقد" + رابط للصفحة الجديدة.
- `src/App.tsx` — Route جديد.

### 6. التخزين والتوافق الخلفي
- نخزّن في `terms` نصاً منظّماً بأقسام مفصّلة بفواصل واضحة (لا تغيير في الـ schema).
- `ContractReviewPanel` يبقى يدعم العقود القديمة (legacy) عبر fallback يعرض الـ terms كما هو + يجلب بيانات المشروع/العرض ويبني الأقسام في الـ runtime.
- لا حاجة لـ migration.

### 7. PDF
نستخدم نفس المكتبة الموجودة (`@react-pdf/renderer` بناءً على وجود `src/components/pdf/`) لإنتاج PDF بنفس تصميم العقد على الشاشة.

## نقاط للتأكيد
1. هل تريد PDF بقالب رسمي بشعار المنصة (نستخدم نفس قالب الفواتير الموجود) أم تصميم بسيط؟
2. هل تريد إضافة "البنود الإضافية" قابلة للتعديل من الجمعية، أم نكتفي بنطاق العمل فقط؟
3. هل صفحة الأدمن تكون قراءة فقط أم نسمح للأدمن بتعديل العقد في حالات استثنائية؟

أوافق وأبدأ التنفيذ بعد ردك على النقاط أعلاه (أو ابدأ مباشرة بالخيارات الافتراضية: PDF بقالب رسمي، نطاق العمل فقط قابل للتعديل، أدمن قراءة فقط).
